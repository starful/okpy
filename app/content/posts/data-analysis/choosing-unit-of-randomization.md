# 実験におけるランダム化単位の選び方：A/Bテスト設計ガイド

### ランダム化単位が重要な理由

ランダム化単位とは、対照群（コントロール）または施策群（トリートメント）のいずれかに独立して割り当てられる対象のことです。個々のユーザー、単一のセッション、特定のデバイス、あるいは組織全体——この選択は決して些細な問題ではありません。これによって観測値間の**統計的独立性**を維持できるかどうかが決まります。独立性が崩れると、統計検定そのものが信頼できなくなり、**効果量の範囲**に関する結論も揺らいでしまいます。

ランダム化単位を誤って選択すると、次のような問題が生じます。

1. **第一種の誤り（偽陽性）の増加：** 効果が存在しないのに「効果がある」と誤って結論づけてしまう。
2. **統計的検出力の低下：** 実際に存在する効果を検出できず、機会を逃してしまう。
3. **効果推定値の偏り：** 効果の大きさや方向を見誤り、誤った意思決定につながる。
4. **一般化可能性の低下：** サンプルの文脈（スコープ）が狭すぎたり不明確になったりし、結果を広く適用しづらくなる。

こうした問題の根底にあるのは、統計的独立性の侵害です。ある単位への施策割り当てが——同じグループ内であれ、グループ間であれ——別の単位の結果に影響を及ぼすと、標準的な統計検定が前提とする仮定が崩れます。これは「リーケージ（漏出）」や「コンタミネーション（汚染）」として現れることが多いです。

### 実験で使われる代表的なランダム化単位

#### 1. ユーザー単位のランダム化

**定義：** 個々のユーザーを対照群・施策群にランダムに割り当て、デバイスやセッション、活動内容に関わらず実験期間中そのグループに固定し続けます。

**メリット：**
- **高い統計的独立性：** 正しく実装されれば、ユーザー単位のランダム化は一般的に最も高い独立性を提供します。あるユーザーの行動が他のユーザーの施策体験に直接影響を与えることは稀なため、**効果量の範囲**を頑健に推定し、結果への**信頼性**を高めやすくなります。
- **一貫したユーザー体験：** ユーザーの体験が安定するため、長期的なエンゲージメントやリテンションの測定、ユーザーの混乱回避に有利です。
- **累積指標に強い：** コンバージョン率、リテンション、LTV、累積機能利用など、ユーザーのジャーニー全体に関わる指標の測定に適しています。

**デメリット：**
- **リーケージのリスク（複数デバイス・アカウント共有）：** ユーザーが複数のデバイスから製品にアクセスしたり、アカウントを共有している場合、一貫したユーザーIDに基づく割り当てでない限り、両方の条件を経験してしまう可能性があります。
- **永続的なユーザー識別が必要：** セッションやデバイスを横断した一意のIDの堅牢なトラッキングに依存します。
- **短期的な効果の観測には不向き：** 割り当てが固定されているため、セッションごとに変動しうる即時的な短期効果が、ユーザー全体の行動パターンの中に埋もれてしまう可能性があります。

**いつ使うべきか：**
- 一貫した長期的なユーザー体験が重要な実験——製品機能テスト、価格施策、パーソナライゼーションの取り組みなど——において、最も一般的かつ推奨される選択です。
- サブスクリプション、チャーン（解約）、リピート購入など、個々のユーザーの時系列的な行動に紐づく指標を測定する場合。

#### 2. セッション単位のランダム化

**定義：** ユーザーが新しいセッションを開始するたびに、独立して対照群・施策群に割り当てられます。同一ユーザーが、異なるセッションで対照群・施策群の両方を経験する可能性があります。

**メリット：**
- **セッション依存的な効果を迅速に収集：** セッション内の即時的な行動や短期的なUI/UX変更に関するデータを素早く収集できます。
- **一時的な介入に有効：** 介入が極めて短命であったり、セッション内の単発的なやり取り（一度限りのポップアップ、その検索クエリに限定された検索結果レイアウトなど）に限定される実験に適しています。
- **永続的なユーザーIDへの依存が少ない：** セッションを横断した堅牢なユーザー識別が難しい場合でも、この手法を使える余地がありますが、それ自体にリスクが伴います。

**デメリット：**
- **統計的独立性が容易に侵害される：** 同一ユーザーが対照群と施策群の両方を経験すると、大きなコンタミネーションとバイアスが生じます。あるセッションでユーザーが経験した内容は、新しい割り当てに関わらず次のセッションの行動に影響を与える可能性があり、真の**効果量の範囲**を分離することが極めて困難になります。
- **ユーザーの混乱・不満：** 同一ユーザーに対する体験の不整合は不満を招き、両群のエンゲージメント指標に影響を及ぼす可能性があります。
- **分析がより複雑になる：** 観測値がもはや独立していないため、ユーザー内の相関を考慮したより高度な統計手法が必要となり、結果への**信頼性**に影響します。

**いつ使うべきか：**
- 介入が本当に単一セッション内に限定され、後続のセッションに持続的な影響を与えないと確信できる、非常に限定的なシナリオでのみ使用してください。
- 例：一度限りの通知、特定のクエリ結果のレイアウト（ユーザーが離脱して完全に独立した新しい検索に戻るケース）、持続的な効果がないと想定されるセッション内バナー広告のバリエーションなど——ただし、このようなケースは稀です。
- **注意：** ユーザー行動を時間をかけて変化させることを意図した介入には、**リーケージ**のリスクが高く**統計的独立性**を欠くため、一般的に推奨されません。

#### 3. グループ/クラスター単位のランダム化

**定義：** チーム、組織、地域、あるいは特定のレガシーシステムの利用者など、ユーザーのグループ全体やクラスター全体をまとめてランダム化します。

**メリット：**
- **スピルオーバー・リーケージの緩和：** 介入が本質的にグループ全体に影響を与える場合、またはグループ内の個人間でのコンタミネーションが避けられない場合に不可欠です。例えば、チーム向けの新しいコラボレーション機能をテストする場合、チーム全体を同じグループに入れる必要があります。
- **「社会的」独立性の保持：** 密接に交流する個人同士が対照群・施策群に分断されるのを防ぎ、特定の実験にとって重要となりうる自然な社会的ダイナミクスを保持します。

**デメリット：**
- **統計的検出力の低下：** 十分な検出力を得るには、個人の数ではなくクラスターの数を大幅に増やす必要があることが多く、これは「実効サンプルサイズ」が個人数ではなくクラスター数になるためです。これは意味のある**効果量の範囲**を検出する能力に直接影響します。
- **分散の増大：** クラスター間の分散は大きくなりがちで、施策効果を見分けるのが難しくなります。
- **バランス調整の難しさ：** 単位の数が少なく大きいため、対照群と施策群の間で属性や利用パターンのバランスを取ることがより困難になります。
- **一般化の難しさ：** サンプルの文脈が、選んだクラスターの特定の種類に大きく依存してしまう可能性があります。

**いつ使うべきか：**
- 介入が個人よりもグループに影響を与える場合（例：新しいチーム向けコミュニケーションツール）。
- **リーケージ**や「ネットワーク効果」が大きな懸念事項であり、個人単位のランダム化では独立性を確保できない場合（例：バイラル性のある製品機能のA/Bテスト）。
- 企業全体が同一の体験を見る必要がある、エンタープライズアカウント向けの価格施策や機能をテストする場合。

### リーケージとコンタミネーションの危険性

**リーケージ**（スピルオーバーやコンタミネーションとも呼ばれる）とは、ある単位の施策割り当てが意図せず別の単位の結果や体験に影響を与え、**統計的独立性**を損なう現象です。これは**実験設計**の妥当性に対する重大な脅威となります。

**リーケージの例：**

- **デバイス・アカウントの共有：** あるユーザーが対照群に割り当てられているが、同じデバイスやアカウントを共有する家族が施策に触れてしまう。
- **ユーザー間のコミュニケーション：** 施策群のユーザーが対照群の友人に新機能について話し、その友人の行動に影響を与える。
- **プラットフォーム全体への変更：** 特定のユーザーセグメント（施策群）を対象とした最適化が、意図せず対照群を含むシステム全体の性能や体験に影響を与える。
- **セッション単位ランダム化に起因する欠陥：** 前述の通り、ある「施策」セッションで起きたことが後続の「対照」セッションの行動に影響を与える場合、観測値はもはや独立していません。

**影響：**
リーケージは一般的に効果推定値をゼロ方向にバイアスさせ、実際の効果の検出を難しくし（検出力の低下）、あるいはその真の大きさを隠してしまいます。場合によっては、効果をゼロから遠ざける方向にバイアスさせ、偽陽性を生み出すこともあります。いずれの場合も、**効果量の範囲**に対する理解を歪め、意思決定における**信頼性**を損ないます。

### ランダム化単位を選ぶためのプロセス

最適なランダム化単位を選ぶことは、体系的なプロセスです。頑健な**実験設計**のために、以下のステップに従ってください。

1. **因果的な問いと介入内容を定義する：**
   - 具体的にどのような変更を導入するのか？
   - この変更に直接さらされる最小単位は何か？
   - 測定したい主要な結果指標は何か？
   - *例：* 新しいオンボーディングフローをテストする場合、介入は*新規ユーザー*に適用されます。ボタンの色をテストする場合、介入はそのボタンを見る*ユーザー*に適用されます。

2. **行動の自然な単位を特定する：**
   - 主にどの行動に影響を与え、測定したいのか——個人の全体的なエンゲージメント（ユーザー）なのか、短い時間枠内の単発的なやり取り（セッション）なのか？
   - *ヒント：* 効果が単発のやり取りを超えて持続することが予想される場合、あるいは記憶や学習が関わる場合は、一般的にユーザー単位のランダム化の方が安全です。

3. **干渉やリーケージの可能性を評価する：**
   - これが最も重要なステップです。ある単位への施策割り当てが別の単位の体験や結果に影響を与える可能性のある、すべての経路を洗い出してください。
   - 共有リソース、ソーシャルネットワーク、マルチデバイス利用、そして介入の時間的性質を考慮してください。
   - より小さな単位（セッションなど）が大きなリーケージのリスクを伴うと判断した場合は、より大きく、より独立性の高い単位（ユーザー単位、あるいはグループ単位）に移行する必要があります。
   - *参考：OKPy Data Analysisのインサイトカード：* **効果量の範囲**とサンプルの文脈を正しく理解できるかどうかは、施策効果を正しく分離できているかどうかに大きく依存します。リーケージはこれを不明瞭にします。

4. **統計的検出力への影響を評価する：**
   - 選択したランダム化単位によって、統計的に有意な効果を検出するために必要な観測数が変わります。特にクラスター単位のランダム化では、クラスター内相関を補うために全体のサンプルサイズを大幅に増やす必要があることが多いです。
   - 選択した単位のレベルで分散を推定してください。実際には存在しない独立性を前提とすると、実験の検出力が不足してしまいます。
   - *OKPy Data Analysisのインサイトカードを活用：* **信頼性**と**効果量の範囲**を確認し、選択した単位がサンプルサイズの要件や効果推定の精度にどう影響するかを把握してください。

5. **実装・トラッキングの実現可能性を検討する：**
   - 選択した単位（一貫したユーザーID、正確なセッション定義など）を、分析システムで確実に割り当て・追跡できるか？
   - 特定の単位を実用的でなくしたり、エラーを生みやすくする技術的な制約はあるか？
   - 堅牢な実装は、データ品質と**実験設計**の妥当性にとって不可欠です。
