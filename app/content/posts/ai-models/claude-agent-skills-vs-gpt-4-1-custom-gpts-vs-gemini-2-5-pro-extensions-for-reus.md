# Claude Agent Skills vs GPT-4.1 Custom GPTs vs Gemini 2.5 Pro Extensions ― 再利用可能なエージェント機能の比較（2026年11月時点）

![cover](https://storage.googleapis.com/ok-project-assets/okpy/20261117110431.jpg)


> 本記事で紹介するモデル名・機能名・料金は執筆時点（2026年11月）の情報です。LLM各社の提供形態は頻繁に更新されるため、実際の導入前には各ベンダーの公式ドキュメントで最新情報をご確認ください。本記事は特定ベンダーを推奨するものではなく、各アプローチの設計思想と向き不向きを整理することを目的としています。

生成AIを業務に組み込む際、多くのチームが直面するのが「同じ指示や手順を毎回書き直したくない」という課題です。社内の校正ルール、特定フォーマットでの出力、繰り返し使うワークフローなどを、どのように“再利用可能な単位”としてLLMに持たせるか。これに対して主要ベンダーはそれぞれ異なる設計思想で答えを出しています。

Anthropicの「Agent Skills」はClaudeに後付けできる手順書とスクリプトの集合体、OpenAIの「Custom GPTs」はChatGPT上で動くカスタマイズ済みアシスタント、Googleの「Gemini Extensions」はGoogleサービスや外部ツールとの連携を主眼にした拡張機能です。名前は似ていますが、設計目的と再利用のされ方はかなり異なります。本記事ではこの3つを横断的に比較します。

## 各モデル・機能の概要

### Claude Agent Skills（Anthropic）

Agent Skillsは、ClaudeやClaude Code上で動く「手順とリソースのパッケージ」です。Markdownで書いた指示書（SKILL.mdのような形式）に加えて、スクリプトやテンプレートファイルを同梱できる点が特徴です。Claudeはタスクの内容に応じて、どのSkillを読み込むべきかを自律的に判断し、必要な部分だけをコンテキストに展開します。

設計の軸は「手順の外部化」にあります。プロンプトに毎回同じ指示を書く代わりに、手順書そのものをファイルとして保持し、複数のプロジェクトやチームで共有・バージョン管理できるようにする発想です。コードレビューのチェックリスト、デプロイの手順、社内特有のドキュメント生成ルールなど、手続き的な知識の再利用に向いています。

### GPT-4.1世代のCustom GPTs（OpenAI）

Custom GPTsは、ChatGPTの画面上でシステムプロンプト・知識ファイル・外部アクション（API連携）・会話開始時の設定をまとめて「一つのアシスタント」として保存できる機能です。GPT-4.1世代でもこの仕組みは継続して利用されており、GPTストアで公開・共有することも可能です。

設計思想は「人格化されたアシスタントの配布」に近く、エンドユーザーがChatGPTの画面からすぐに呼び出して使うことを前提としています。社内FAQボット、特定業務のアシスタント、ブランドトーンを固定したライティング支援など、対話型のユースケースに強みがあります。一方で、API経由でプログラム的に呼び出す用途としては、通常のAPIにシステムプロンプトとfunction callingを組み合わせる形がより一般的です。

### Gemini 2.5 Pro Extensions（Google）

Gemini Extensionsは、Gemini AppやGoogle Workspaceと連携する形で提供される拡張機能群です。Google検索、Gmail、Google マップ、YouTubeなど、Googleの既存サービスをGeminiの会話の中から呼び出せるようにする仕組みが中心で、開発者が独自に定義する「スキル」の自作・配布という文脈とは少し軸が異なります。

Gemini 2.5 ProはGoogle AI Studio・Vertex AI経由でもAPIとして利用可能で、こちらでは関数呼び出し（Function Calling）やツール定義を自分で構築する形が主流です。つまり「拡張機能としてのExtensions」と「API上でのツール呼び出し設計」は別物として捉える必要があります。

| 主な配布経路 | ファイル共有・リポジトリでのバージョン管理が前提 | GPTストアでの公開・社内共有リンク | Google Workspace・Gemini App内での有効化 |

## 料金感の整理

厳密な金額の比較は変動が大きいため避けますが、おおまかな位置付けは次のように整理できます。

- **個人・小規模利用**：いずれのベンダーも無料〜数千円/月程度の個人向けプランで、基本的な機能のカスタマイズ（Skillの利用、Custom GPTsの作成、Extensionsの有効化）は可能です。
- **チーム・ビジネス利用**：Team/Business向けプランでは、組織内での共有機能やガバナンス機能（アクセス制御、利用ログなど）が追加される傾向にあり、月額は個人プランより高くなります。
- **API/開発者利用**：Claude APIやVertex AI経由でのGemini利用、OpenAI APIはいずれも従量課金（トークン数ベース）で、Custom GPTs自体のAPI直接呼び出しという概念は薄く、通常のAPI利用料に収まります。

コストを考える際は「アシスタントやSkillを作る・管理する手間」も含めた総コストで比較すべきです。GUIで完結するCustom GPTsは初期コストが低い一方、手順が複雑になると管理が難しくなりがちです。Agent Skillsはファイルベースのため初期学習コストはやや高いものの、チームでの共有・バージョン管理が効きやすい設計です。

## ユースケース別の向き不向き

- **社内ナレッジを手順化して複数人・複数プロジェクトで使い回したい** → Agent Skillsのようなファイルベースの手順書管理が向いています。コードレビュー基準、ドキュメント生成ルールなど、手続きが明確なタスクに強みがあります。
- **非エンジニアのスタッフにもすぐ使える対話アシスタントを配布したい** → Custom GPTsのようなGUI完結型の仕組みが導入のハードルを下げます。社内FAQ、文章トーンの統一などに向いています。
- **既存のGoogleサービス（検索・メール・マップなど）と連携した情報収集を会話の中で行いたい** → Gemini Extensionsのようなサービス連携型の拡張が適しています。
- **プログラムから自動的にツールを呼び出す複雑なワークフローを組みたい** → いずれのベンダーもAPI＋Function Calling（Tool Use）の組み合わせが基本線になり、GUI上の「配布用機能」とは別の設計が必要になります。

## 選び方の考え方

ベンダー選定を「どのAIが優秀か」という軸だけで決めるのは危険です。再利用可能なエージェント機能に関しては、次の順序で検討するのが実務的です。

1. **再利用したいものの性質を切り分ける**：手順（どうやるか）なのか、人格・トーン（どう話すか）なのか、外部サービス連携（何と繋がるか）なのかを明確にする。
2. **運用者のスキルセットを考慮する**：エンジニアが手順書をファイルで管理できるならAgent Skills的なアプローチ、非エンジニア中心ならGUI完結型のアプローチが現実的です。
3. **既存の社内インフラとの親和性を見る**：Google Workspaceを全社導入している組織であればGemini系の連携が自然に効き、Slack/GitHub中心の開発チームであればClaude CodeやAPI経由の統合が扱いやすい場合があります。
4. **ロックインの度合いを確認する**：手順書やプロンプトがどの程度ポータブルか（他のモデルに移植しやすいか）は、中長期の運用コストに直結します。
5. **小さく試してから広げる**：いずれの仕組みも、最初から全社展開するのではなく、一つの業務フローに限定して試験導入し、効果と運用負荷を見てから拡大するのが無難です。

## FAQ

**Q1. Agent SkillsとCustom GPTs、Extensionsは排他的に選ぶものですか？**
いいえ、必ずしも排他的ではありません。例えば社内の定型業務はAgent Skills的な手順書で管理しつつ、顧客対応用の対話アシスタントはCustom GPts的なGUIベースの仕組みで配布し、Google系ツールとの連携だけはExtensionsに任せる、といった併用も現実的です。重要なのは「何を再利用したいのか」を機能ごとに切り分けて考えることです。

**Q2. 小規模なチームでも導入する価値はありますか？**
手順が頻繁に繰り返される業務（定型レポート作成、特定フォーマットでのレビュー、決まった手順のデータ整形など）が一つでもあれば、小規模チームでも効果は出やすいです。逆に、業務内容が毎回大きく異なる場合は、カスタマイズの手間に対して得られる再現性のメリットが小さくなることがあるため、まずは最も繰り返し頻度の高い一つの業務に絞って試すのがおすすめです。

**Q3. 料金プランが変わった場合、この記事の比較表は信頼できなくなりますか？**
料金の絶対額やプラン名は変わる可能性が高いため、本記事では意図的に「帯感」としての比較に留めています。選定の際は、本記事で示した「設計思想の違い」や「向いているユースケースの型」を参考にしつつ、実際の料金・機能詳細は各ベンダーの公式ドキュメントで最新情報を確認することを推奨します。
