# 데이터 처리 모델 비교: OLTP와 OLAP

### OLTP와 OLAP 데이터 모델의 차이점과 설계 포인트

![image](https://storage.googleapis.com/ok-project-assets/okpy/20250609182316.png)

OLTP(Online Transaction Processing)와 OLAP(Online Analytical Processing)는 데이터베이스의 사용 목적에 따라 구분되는 두 가지 대표적인 데이터 처리 모델이다. 각각의 용도, 특징, 설계 사상의 차이를 이해하고 목적에 맞는 데이터 모델링을 하는 것이 시스템 성능과 비즈니스 성과를 크게 좌우한다.

---

## 1. OLTP란?

OLTP는 일상 업무에서 발생하는 트랜잭션 처리(등록·수정·삭제 등)를 빠르게 처리하는 시스템을 말한다.

* **주요 용도**: 주문 처리, 고객 관리, 재고 관리, POS 등
* **특징**:

  * 소량 데이터에 대한 빈번한 읽기·쓰기
  * 정규화된 스키마 구조
  * 빠른 응답 속도와 높은 동시 접속 처리
  * 데이터 정합성과 ACID 트랜잭션을 중시

> 예: 한 리테일 체인은 각 매장의 POS 단말기가 실시간으로 매출을 기록하고 재고를 갱신하는 구조를 OLTP로 구현했다. 트랜잭션 1건당 처리 시간은 0.1초 이내다.

---

## 2. OLAP란?

OLAP는 축적된 대량 데이터를 집계·분석하기 위한 모델이다.

* **주요 용도**: 매출 분석, 트렌드 분석, KPI 대시보드, BI 리포트
* **특징**:

  * 대량 데이터에 대한 복잡한 집계·분석 쿼리
  * 비정규화된 스타(Star)/스노우플레이크(Snowflake) 스키마 채택
  * 응답 속도보다 분석의 유연성을 중시
  * 최종적 일관성(Eventually Consistent)만으로도 충분한 경우가 많음

> 예: 같은 리테일 체인은 월별 매출 리포트를 OLAP 기반 데이터 마트로 생성한다. 전 매장·전 상품 카테고리를 아우르는 집계가 가능하며, 쿼리 1회로 1천만 건 이상의 데이터를 처리한다.

---

## 3. 모델링 설계 사상의 차이

| 비교 항목     | OLTP 모델      | OLAP 모델                |
| --------- | ------------ | ----------------------- |
| 목적        | 업무 트랜잭션 처리   | 데이터 분석과 시각화             |
| 데이터 구조    | 정규화          | 비정규화(스타형, 스노우플레이크형)     |
| 갱신 빈도     | 높음(빈번한 쓰기)   | 낮음(주로 읽기)               |
| 사용자       | 업무 담당자, 시스템  | 분석가, 경영진                |
| 트랜잭션 모델   | ACID         | BASE 또는 배치 동기화          |

---

## 4. 하이브리드 설계와 ETL의 역할

실제 시스템에서 OLTP와 OLAP는 독립적으로 존재하지 않고, ETL(Extract, Transform, Load) 과정을 통해 서로 연결된다.

* **ETL 흐름**:

  * OLTP에서 수집된 데이터를 주기적으로 추출(Extract)
  * 집계, 비정규화, 클렌징 등을 수행(Transform)
  * 데이터 웨어하우스나 데이터 마트에 적재(Load)

> 예: 한 이커머스 사이트는 OLTP의 주문 데이터를 1시간마다 배치 처리로 OLAP 환경에 반영한다. 이를 통해 실시간성과 분석성을 동시에 확보한다.

---

## 5. 자주 발생하는 실수와 주의점

* OLTP에 집계용 쿼리를 섞어 써서 처리 지연이 발생하는 경우
* OLAP에 지나치게 정규화된 구조를 적용해 분석이 어려워지는 경우
* ETL 처리가 무거워져 분석 환경 갱신이 지연되는 경우

---

#### 정리

OLTP와 OLAP는 역할도 설계 방침도 명확히 다르지만, 비즈니스를 떠받치는 정보 기반으로서는 서로를 보완하는 두 바퀴다. 실시간으로 신뢰할 수 있는 데이터를 기록하고(OLTP), 이를 활용해 미래의 의사결정을 이끌어내는(OLAP) 구조를 완성하려면 목적에 맞는 데이터 모델링과 아키텍처 설계가 반드시 필요하다.

그리고 가장 중요한 것은 현장에서 어떻게 쓰일지를 상상하며 설계하는 일이다. 데이터 모델은 기술이지만, 궁극적으로는 "사람의 행동"을 떠받치는 구조여야 한다.
