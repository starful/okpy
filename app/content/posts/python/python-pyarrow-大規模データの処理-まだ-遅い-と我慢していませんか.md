# Python PyArrow: 대용량 데이터 처리, 아직도 "느리다"며 참고 계신가요?

![image](https://storage.googleapis.com/ok-project-assets/okpy/20260214114259.png)

📝 **TL;DR (3줄 요약)**

1. PyArrow는 데이터를 빠르게 주고받을 수 있게 해주는 "Apache Arrow"의 Python용 라이브러리로, 특히 대규모 데이터의 읽기/쓰기를 획기적으로 빠르게 만들어줍니다.
2. 메모리 효율을 극대화하는 "컬럼나(열 지향) 포맷"을 채택하고 있어, Pandas 같은 다른 라이브러리와 연동할 때 불필요한 데이터 변환을 없애줍니다.
3. 대용량 CSV 읽기나 Parquet 파일 처리에서 기존 방식보다 수 배에서 수십 배의 성능을 내는, 현대 데이터 분석에 필수적인 도구입니다.

***

### 1. 🤔 PyArrow란 대체 무엇인가? (핵심 역할과 주요 사용 사례)

#### **핵심 역할: 데이터 세계의 "표준 컨테이너"**
Python으로 데이터 분석을 막 시작했을 때, 많은 사람이 "Pandas"로 CSV 파일을 읽고 쓰는 것부터 시작합니다. 하지만 다루는 데이터 크기가 수 GB, 수십 GB로 커지면 "로딩이 끝나지 않는다", "메모리 부족으로 에러가 난다" 같은 벽에 부딪히게 됩니다. 이 문제를 해결하기 위해 등장한 것이 바로 **PyArrow**입니다.

PyArrow를 이해하기 위해 **"국제 물류"**를 예로 들어보겠습니다. 예전에는 화물선으로 짐을 나를 때 짐의 모양과 크기가 제각각이었습니다. 실을 때마다 짐 모양에 맞춰 퍼즐을 맞추듯 배치해야 했고, 내릴 때도 똑같은 작업을 반복해야 했습니다. 이것이 컴퓨터 세계에서 말하는 "직렬화(데이터 구조화)"와 "역직렬화(복원)"로 인한 시간 손실입니다.

여기에 등장한 것이 바로 **"표준 규격 컨테이너"**입니다. 정해진 형태의 박스에 담으면 어느 나라의 항구에서든, 어떤 크레인으로든 내용물을 다시 포장할 필요 없이 그대로 옮길 수 있습니다. **PyArrow(Apache Arrow)는 바로 이 "컨테이너" 역할을 합니다.** Python, R, Java, C++ 같은 서로 다른 언어 사이에서도, Pandas, Spark 같은 서로 다른 도구 사이에서도 데이터를 "다시 포장하는 수고(변환 비용)" 없이 초고속으로 주고받을 수 있게 해주는 마법 같은 기술입니다.

#### **주요 사용 사례: PyArrow가 진가를 발휘하는 순간**
PyArrow는 단독으로 쓰기보다 다른 도구와 조합했을 때 그 위력이 드러납니다. 대표적인 예를 몇 가지 살펴보겠습니다.

1. **Parquet 파일의 고속 읽기/쓰기**
   데이터 분석 세계에서는 CSV보다 효율적인 "Parquet"이라는 파일 형식이 자주 쓰입니다. PyArrow는 이 Parquet 형식을 다루는 데 있어 최강의 엔진입니다. 수백만 행에 달하는 데이터도 PyArrow를 쓰면 순식간에 읽어 들일 수 있습니다. 이는 PyArrow가 "필요한 열만" 정확히 골라 읽는 데 특화되어 있기 때문입니다.

2. **Pandas 처리 속도를 획기적으로 향상**
   Pandas로 거대한 데이터를 다룰 때, 백엔드(내부 처리 엔진)로 PyArrow를 지정할 수 있습니다. 이를 통해 기존 Pandas 단독 처리보다 메모리 소비를 줄이고 계산 속도를 높일 수 있습니다. "Pandas는 편리하지만 느리다"는 통념을 뒤집어주는 강력한 지원군입니다.

3. **메모리를 절약하는 데이터 공유 (제로 카피)**
   보통 프로그램 간에 데이터를 주고받으면 "복사"가 발생해 메모리를 2배로 소비합니다. 하지만 PyArrow는 "제로 카피"라는 기술을 갖추고 있어, 데이터를 복사하지 않고 그대로 참조할 수 있습니다. 덕분에 한정된 메모리 자원으로도 훨씬 거대한 데이터를 다룰 수 있게 됩니다.

### 3. 🛠️ 실제로 동작하는 예제 코드

여기서는 PyArrow로 데이터를 만들고, 이를 효율이 높은 "Parquet 형식"으로 저장·읽기하는 기본 흐름을 소개합니다.

```python
import pyarrow as pa
import pyarrow.parquet as pq
import pandas as pd
import os

# 1. 샘플 데이터 생성 (Pandas 사용)
data = {
    'ID': [1, 2, 3, 4, 5],
    '이름': ['Alice', 'Bob', 'Charlie', 'David', 'Eve'],
    '점수': [85.5, 92.0, 78.5, 88.0, 95.0],
    '등록일': pd.to_datetime(['2023-01-01', '2023-01-02', '2023-01-03', '2023-01-04', '2023-01-05'])
}
df = pd.DataFrame(data)

print("--- 원본 Pandas DataFrame ---")
print(df)

# 2. Pandas에서 PyArrow의 "Table"로 변환
# 이것이 "표준 컨테이너"에 짐을 싣는 작업입니다
table = pa.Table.from_pandas(df)

# 3. Parquet 파일로 저장
file_name = 'sample_data.parquet'
pq.write_table(table, file_name)
print(f"\n파일을 저장했습니다: {file_name}")

# 4. Parquet 파일 읽기
# 필요한 열만 지정해서 읽는 것도 가능합니다 (고속화의 비결)
read_table = pq.read_table(file_name, columns=['이름', '점수'])

# 5. PyArrow Table을 다시 Pandas로 변환해 출력
result_df = read_table.to_pandas()

print("\n--- PyArrow를 통해 읽은 데이터 (특정 열만) ---")
print(result_df)

# 뒷정리 (생성한 파일 삭제)
if os.path.exists(file_name):
    os.remove(file_name)
```

***

### 4. 🔍 코드 상세 설명

위 코드에서 수행하는 작업을, 초보자를 위해 중요한 포인트 위주로 설명하겠습니다.

#### **데이터 "재포장": `pa.Table.from_pandas()`**
이 부분은 우리에게 익숙한 Pandas 형식을 PyArrow 고유의 "Table" 형식으로 변환합니다. 이것이 앞서 설명한 "컨테이너에 짐을 싣는 작업"에 해당합니다. PyArrow의 Table 형식으로 만들면 데이터가 메모리상에서 "열(컬럼)" 단위로 재정리되어, 이후 처리 속도를 높일 준비가 끝납니다.

#### **효율적인 저장: `pq.write_table()`**
Parquet은 데이터 분석에 특화된 파일 저장 형식입니다. CSV는 텍스트 파일이라 사람도 읽을 수 있지만, 컴퓨터 입장에서는 읽어 들이는 데 시간이 걸립니다. 반면 Parquet은 바이너리 형식으로 데이터를 압축해 저장하므로 파일 크기가 획기적으로 작아지고, 읽기/쓰기 속도도 놀라울 만큼 빨라집니다.

#### **필요한 만큼만 꺼내기: `pq.read_table(columns=[...])`**
PyArrow의 진짜 강점이 여기에 있습니다. 예를 들어 100개의 열이 있는 거대한 데이터에서 "이름"과 "점수" 단 2개 열만 필요하다면, PyArrow는 파일 전체를 읽는 대신 그 2개 열이 저장된 위치만 정확히 겨냥해 읽어 들입니다. 이를 "열 지향 읽기"라고 하며, 대규모 데이터 처리에서 극적인 시간 단축을 가능하게 합니다.

#### **분석으로의 복귀: `to_pandas()`**
PyArrow로 빠르게 읽어 들인 데이터는 마지막에 `to_pandas()`만 호출하면 익숙한 Pandas DataFrame으로 되돌릴 수 있습니다. 즉 "무거운 작업(읽기/쓰기)은 PyArrow에 맡기고, 세부 분석은 Pandas로 하는" 양쪽의 장점을 모두 취할 수 있는 것입니다.

***

### 5. ⚠️ 주의 사항 및 팁

#### **① 데이터 타입의 "엄격함"에 주의!**
Pandas는 데이터 타입(정수, 부동소수점, 문자열 등)에 비교적 느슨하지만, PyArrow는 매우 엄격합니다. 예를 들어 하나의 열에 "숫자"와 "문자열"이 섞여 있는 불완전한 데이터를 변환하려 하면 PyArrow가 에러를 낼 수 있습니다.
**팁:** PyArrow를 사용하기 전에 Pandas 쪽에서 `df.convert_dtypes()`를 실행하거나 결측값(NaN) 처리를 적절히 해두면 매끄럽게 연동할 수 있습니다.

#### **② 메모리 매핑 파일 활용**
PyArrow에는 거대한 파일을 메모리에 전부 올리지 않고, 필요한 부분만 디스크에서 직접 참조하는 "메모리 매핑(Memory Mapping)" 기능이 있습니다.
**팁:** `pa.memory_map()`을 사용하면 PC의 메모리 용량을 초과하는 초대형 파일도 PC가 멈추지 않고 매끄럽게 처리할 수 있습니다. 이는 프로 개발자들도 자주 사용하는 테크닉입니다.

***

### 6. 🔗 함께 살펴보면 좋은 라이브러리

**Polars**
PyArrow를 익힌 다음 꼭 확인해보면 좋은 것이 현재 빠르게 인기를 얻고 있는 데이터 처리 라이브러리 **"Polars"**입니다. Polars는 내부적으로 PyArrow와 같은 "Apache Arrow" 구조를 기반으로 만들어졌습니다. Pandas보다 훨씬 빠르고 메모리 효율도 좋으며, PyArrow와의 궁합이 매우 좋은 것이 특징입니다. "PyArrow로 데이터의 기초를 배우고, Polars로 초고속 분석 코드를 작성한다"는 것이 현대 Python 데이터 엔지니어의 정석 루트가 되어가고 있습니다.
